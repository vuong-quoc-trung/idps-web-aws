# R27 native policy-family research cohort

R27 captures three **different application mechanisms** in fresh, offline KVM
guests: ADMIN-only user lookup; principal-resolved self-profile lookup requiring
STUDENT; and a real catalog creation by STAFF versus denial for STUDENT. The
third workflow verifies an actual H2 commit, not only HTTP201. Self-profile
checks the owner bound to the current principal. All labels use Audit principal
and session binding, pinned policy and JDBC/application evidence.

The task is `AUTHORIZATION_POLICY_VIOLATION_ATTEMPT`. These are denied attempts,
not malicious motivation, successful compromise or publisher payload anomalies.
Machine witnesses do not manufacture independent human review. No role labels,
Oracle outcome, status, database changes or resource/actor IDs enter features.

## Data roles and independence

`plan.py` and the private preregistration fix roles **before acquisition**:
user-read TRAIN; self-profile and academic-write DEV. There are 26 planned HTTP
requests, of which six are target requests; the others establish and verify the
real sessions. Different IDs, seeds, usernames or guest boots alone do not
establish independence. The three mechanisms differ in policy branch, resource
resolution and operation, and have counterbalanced roles: each of ADMIN, STAFF
and STUDENT has both an allowed and a denied target.

The graph retains **all setup custody, campaign and session edges**. Exact
feature equivalence is scoped to task, primary ABI and observed profile. The
setup population has a separate session-establishment task, not an eligible
authorization target view. A coarse URI-only baseline or equal unavailable
tensor is not physical identity proof across unrelated tasks. Rejected TARGET
records still bridge roles; verified near/physical/actor/material links are never
removed. Tests prove that a new guest/ID cannot undo a shared material template.

An exhaustive six-target census verifies the three material components; it is
not an approximate/saturated search. This establishes **within-lab structural
disjointness**, not independent sampling from a deployment population. Shared
lab/environment, fixed policy and scripted case selection remain. There are
zero representative independent final exposure anchors. T07 confidence,
calibration, coverage and final-release thresholds remain unchanged.

The R27 admission profile yields six **task-specific research canonical rows**,
TRAIN2 / DEV4. They are eligible for internal supervised research on this narrow
task; DEV remains protected from future TRAIN reuse. The private
`native-source-role-registry.json` must be loaded by any future native intake.
This is an additive T09 profile, not a claim that the unchanged legacy T02 v1
task-enum serializer accepts the new label. The formal/global T07 ATTACK_INTENT
cohort remains unqualified; no CAL/TEST was acquired or unsealed. Never silently
merge these counts or labels with publisher or historical formal datasets.

## Feature and runtime scope

Context22 is an additive version of Context20: the same current-request trusted
principal fields, six resource categories, six missingness states and source
flags. Protected catalog POST is whitelisted because it does not rotate or
mutate authentication. Login/logout and unsupported routes remain WITHHELD.
Owner and database outcomes remain GROUND_TRUTH_ONLY; no stale principal cache
or unverified history is used. URI100 and Context20 versions remain unchanged.

The collector reuses R26.2 immutable versions and timestamps after actual
encoding. Cutoff is still 1,000ms with a 1ms guard. Python/Rust parity covers
1,480 synthetic envelopes in three fresh processes plus all six real target
contexts. The Rust binary is an offline projector, not a new persistent scorer
or an authentication endpoint. Its private binding must come from verified
collector custody. No new model, ONNX or enforcement is deployed.

## Execution

`supervisor.py` serializes build, parity and the three bounded captures through
the existing Resource Adapter. It checkpoints family completion and refuses
redispatch of an attempted directory. Global Adapter allocation is serial.
It now automatically continues to admission, information census and finalizer.
`--finalize-existing` validates committed receipts/admission/role-registry hashes
and runs only offline finalization, without a route to capture or worker dispatch.
That recovery path was executed under a real Resource Adapter: zero additional
HTTP, unchanged receipt SHAs, completion and cleanup verified. The initial R27
acquisition used the earlier capture-only supervisor, followed by managed admission;
the final recovery path completes that same committed namespace.
Safety/ownership/watchdog errors do not auto-restart. KVM has `-nic none` and
the H2 database is guest-owned and disposable. BCrypt cost, actual authentication,
CSRF, session rotation and application policies are unchanged.

`capture.py` only patches private guest staging. Static checks found that the
old catalog seed lacked `majors.short_code` and a safe next identity value for
creation; both are supplied in the owned H2 seed before HTTP. Request transport
supports real JSON POST with same-session CSRF and refreshes CSRF after login.
Startup verifies the actual roles configured for each family, including STAFF.
The role/category/SQL mappings are separately checked against captured state
digests in `admit.py`.

`admit.py`, `information.py` and `finalize.py` verify receipts, features, labels,
lineage, fixed model scores, historical SHAs and cleanup. No publisher holdout,
training experiment or repeated capture is run. Actual research examples have
identical URI100 within each authorized/unauthorized pair; role-only, method-only,
category-only and source-availability-only controls also remain ambiguous.

Known deterministic policy resolves the six targets. No independent added ML
benefit is demonstrated, so no classifier is trained to learn that lookup.
B16 remains the publisher research candidate; Notes/PKDD generalization failures
are not repaired by these authorization examples. RI v2 remains default, R20
remains shadow, and existing healthy services are not restarted.

Clean-checkout packaging of the legacy capture dependencies/private models is
not certified. No official release is attempted while quality gates are blocked.
